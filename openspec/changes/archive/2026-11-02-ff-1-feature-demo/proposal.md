# Proposal

## Why

Request #1 (change): Feature: DEMO

Build a full-stack **User Management Web Application** using **React (TypeScript)**, **Golang**, and **MongoDB**. The application must support the complete user management lifecycle: creating, viewing, updating, activating, deactivating, searching, filtering, and deleting user records.

## What Changes

Greenfield repo (only `README.md`). Build a User Management app. The backend is Go (latest stable release, per the reviewer's feedback) using the official MongoDB Go Driver, in Handler → Service → Repository layers. The frontend is React + TypeScript (Vite). Docker Compose runs the frontend, backend and MongoDB. Backend and frontend are separate, independently buildable apps under `backend/` and `frontend/`.

- Create backend/ with go.mod (latest Go version, mongo-driver v2, testify) and cmd/server/main.go. main.go loads the config, connects to MongoDB with a ping, ensures the unique email index, starts the server and shuts down gracefully on SIGINT/SIGTERM.
- backend/internal/config/config.go: env-based config with PORT, MONGODB_URI, MONGODB_DB, CORS_ALLOWED_ORIGIN, MAX_BODY_BYTES and LOG_LEVEL. Fail fast if a required value is missing. Add backend/.env.example.
- backend/internal/model/user.go: the User struct with bson/json tags, status constants, and the request/response DTOs.

- backend/internal/repository/user_repository.go: a UserRepository interface and a Mongo implementation with Create, GetByID, List (BSON filter, regexp.QuoteMeta search, skip/limit, sort by createdAt desc), Update, UpdateStatus, Delete and Stats (counts). Every method takes a ctx. Add EnsureIndexes.
- backend/internal/service/user_service.go: validation (required fields, email via net/mail, phone format, length limits, trimmed and lowercased email), ObjectID parsing, status validation, and timestamp handling.
- backend/internal/handler/ (users handler, response helpers) and middleware/ (CORS for the single origin, http.MaxBytesReader, request logging with slog, panic recovery). Wire the routes in backend/internal/server/router.go.
- Backend tests (see the Test plan).
