## What Changes

The ForgeFlow backend already serves `GET /api/v1/users/{id}`. It is registered at `backend/internal/handler/user_handler.go:25` and handled by `get` and `UserService.Get`. It already returns 200, 400 for a malformed id, and 404 for a missing user. The 500 path comes from `apperror.As` and `FromMongo`. So this change adds no new route. It checks the existing endpoint against each acceptance criterion and fills the test gaps. Production code changes only if a new test shows a criterion is not met.

- In backend/internal/handler/user_handler_test.go, add a test that parses the 200 response of GET by id. It checks success=true, data.id, data.email and data.firstName, and that there is no error field.
- In the same file, extend the 400 and 404 coverage to parse the body. It checks success is false, error.code is VALIDATION_ERROR or NOT_FOUND, and error.message is "Invalid user ID." or "User not found.". Include a whitespace id (%20) and a wrong-length hex id.
- In the same file, add a 500 test. Set repo.Err = errors.New("boom db failure"), which avoids the words "connection" and "server selection". GET a valid ObjectID hex and expect 500, code INTERNAL_ERROR, and a body that does not contain the raw error text.
- In the same file, add a test for the missing-id request GET /api/v1/users/. It asserts the status the router actually returns, then resolves open question 2.
